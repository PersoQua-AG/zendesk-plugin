Zendesk in Claude Desktop einrichten

Vier Schritte, etwa fünf Minuten. Du brauchst die Datei zendesk-1.0.0.mcpb und Zugang zu 1Password. Es gibt kein Archiv und nichts zu entpacken — leg die Datei irgendwo ab, wo du sie im Dateidialog wiederfindest.

Einrichten

  1. 1Schritt 1 · Erweiterung installieren

    In Claude Desktop: Einstellungen (Settings) → Erweiterungen (Extensions) → Erweiterte Einstellungen (Advanced settings) → Erweiterung installieren… (Install extension…), dann zendesk-1.0.0.mcpb auswählen.

    Die Zwischenstufe Erweiterte Einstellungen (Advanced settings) ist die Stelle, an der man hängenbleibt: Ohne sie gibt es den Punkt zum Installieren nicht.

  2. 2Schritt 2 · Drei Felder ausfüllen

    Claude Desktop fragt danach neun Angaben ab. Nur diese drei trägst du ein:

    • Zendesk Subdomain → kundenservice
    • OAuth Client ID → aus 1Password
    • OAuth Client Secret → aus 1Password

    Die übrigen sechs Felder bleiben unverändert.

  3. 3Schritt 3 · Anmelden — zwei Aufrufe

    Das ist die Stelle, an der es aussieht, als sei etwas kaputt. Ist es nicht: Die Anmeldung braucht zwei Aufrufe von zendesk_login, mit deiner Bestätigung im Browser dazwischen.

    Erster Aufruf. Schreib in einen neuen Chat: „Melde mich bei Zendesk an“. Die Antwort lautet: 

    Zendesk authorization started. Open this URL in your browser and approve access:
https://…
Then run zendesk_login a second time to finish — this call does not wait for you.
The authorization stays open for 5 minute(s); after that, run zendesk_login to start over.

    Im Browser bestätigen. Adresse öffnen, Zugriff erlauben. Der Tab zeigt dann Authorized. You can close this tab. Dafür hast du fünf Minuten.

    Zweiter Aufruf. Zurück im Chat: „Führe zendesk_login noch einmal aus“. Fertig ist es bei: 

    Authorization complete — the Zendesk credentials are stored encrypted and are
refreshed automatically. Verify with zendesk_get_me.

  4. 4Schritt 4 · Prüfen

    Frag im Chat: „Wer bin ich in Zendesk?“ Kommt dein Name aus Zendesk zurück, läuft es.

Was die Erweiterung nicht tut: Löschen, Zusammenführen und Schwärzen sind nicht eingebaut. Hat sich ein Ticket geändert, seit Claude es gelesen hat, überschreibt sie nicht, sondern meldet Conflict: ticket #… changed since last read ….

Was nicht funktioniert: die Befehle mit Schrägstrich (/zendesk:tickets und die anderen) — die gibt es nur in Claude Code. Hier fragst du in normaler Sprache.

Wenn etwas klemmt

Eine Meldung nennt ein leeres Feld

Missing required environment variable: ZENDESK_OAUTH_CLIENT_SECRET (extension
configuration field "oauth_client_secret" is empty). Open Settings → Extensions →
Zendesk, complete the configuration, then reload the extension.

Die Meldung nennt den internen Feldnamen: zendesk_subdomain ist Zendesk Subdomain, oauth_client_id ist OAuth Client ID, oauth_client_secret ist OAuth Client Secret. Trag den Wert nach und lade die Erweiterung neu (reload the extension) — ein neuer Chat genügt nicht, die Werte werden beim Start der Erweiterung gelesen.

„No Zendesk authorization found“

No Zendesk authorization found. Run the zendesk_login tool to authorize (from a terminal: `npm run authorize`).

Den Teil in Klammern ignorierst du — er gilt nur für Entwickler; mach stattdessen Schritt 3.

Steht dort stattdessen Stored Zendesk credentials could not be read (encryption secret changed or file corrupt). Run the zendesk_login tool to re-authorize., wurde das Client-Secret gewechselt: neues Secret aus 1Password eintragen, Erweiterung neu laden, dann Schritt 3. zendesk_login selbst meldet denselben Fall kürzer, mit Stored credentials could not be read … — starting a new authorization., und beginnt sofort eine neue Anmeldung.

Die fünf Minuten sind abgelaufen

Zendesk login failed: OAuth callback timed out after 300000ms.
Run zendesk_login again to start a new authorization.

300000ms sind die fünf Minuten, und trotz failed ist nichts kaputt. Dieser Aufruf räumt nur die abgelaufene Anmeldung weg — die neue Adresse liefert erst der Aufruf danach. Also zendesk_login ein zweites Mal ausführen lassen und die Adresse diesmal gleich öffnen.

Entfernen

Unter Einstellungen (Settings) → Erweiterungen (Extensions). Deine Anmeldung liegt außerhalb des Erweiterungsordners und bleibt dabei liegen — deshalb übersteht sie auch eine Aktualisierung. Soll sie weg, lösch den Ordner ~/Library/Application Support/zendesk-plugin (macOS) beziehungsweise %APPDATA%\zendesk-plugin (Windows) von Hand.
